# Gateway-owned groups in Desktop

Bot Mode lists gateway rooms separately from legacy renderer rooms. Refresh gateway groups reloads the selected connection/profile's canonical room list. Opening a room captures that exact authority; changing the foreground profile does not retarget its controls.

With `groups.capabilities.driver` enabled, the existing creation dialog creates a canonical group. Only same-authority local-profile members are supported; Desktop connection descriptors are not peer grants. Existing legacy rooms offer **Start gateway group** instead of renderer-owned execution. This starts a new room and deliberately does not replay legacy history.

The gateway owns the log and work. Desktop reads `groups.state` and `groups.log`, sends through `groups.send`, and stops through `groups.stop`. Pending actions come only from `driver_status.pending_actions`. Discard requires explicit confirmation that prior side effects are not undone; Retry and approvals retain the exact member/task/generation/request identity. Errors remain visible and no failed canonical mutation falls back to hidden-session submission.

Rename, disband and membership editing are not offered here. Room discovery is durable on the gateway rather than replicated through Desktop ui_meta. Ambiguous send retries preserve their event identity while the workspace remains mounted; native crash-safe group-send journaling is not implemented.

## Files

A message can carry files: the composer uploads each one with `groups.attachment.upload` before Send, and each message in the history offers **Download** (`groups.attachment.download`, by the message's `event_id` and the file's `attachment_id`). A Bot's shared files arrive the same way, on its `message.member` reply, so they download and list like yours (`producer.kind: 'member'`, with the Bot's name).

The room header offers **Files** when the gateway's `groups.capabilities` `methods` lists `groups.attachment.list`. Desktop reads it once per visible room view, and again every two seconds after a failed read while the room is visible; an answer without a method list never offers Files. The standalone server (`hermes serve`, `hermes dashboard`) serves no attachments, so Files does not appear there.

- **List** (`canonical-files-client.ts`): `groups.attachment.list` with `limit: 8`, plus `query` while searching and `cursor` for **Older**. The gateway lists newest share first, then message order, and matches `query` against file names and sharers, ignoring case and accents. Desktop checks every page: this room, an authority (`gateway_id`, `epoch`), a `snapshot_seq` no row exceeds, that order, `has_more` matching `next_cursor`, and each row's fields, including a date it can show. A page that fails any check is an error with **Retry**, never half a list. A reply for an earlier search is dropped.
- **Pages:** **Older** continues the first page's `snapshot_seq` and authority, so files shared meanwhile never shift pages; a continuation that changes either, repeats a cursor or goes backwards is refused like a cursor the gateway refuses (`attachment_cursor_invalid`): **Show latest** starts again from the newest files. **Show latest** also appears when the room log has a file-bearing message newer than the list's snapshot. A sparse search may return a short or empty page that still has **Older**.
- **Rows:** one row per exact version (`event_id` + `attachment_id`), with its sharer (the gateway's `You` for your own shares is shown in your language), time to the second, type and size, so two files with the same name stay two rows.
- **Download** fetches that version with `groups.attachment.download` and saves it through the browser download the history uses (`canonical-attachment-download.ts`) only when the reply's `event_id`, `attachment_id`, `name`, `kind`, `mime` and `size` match the row and the bytes' SHA-256 matches `sha256`; otherwise nothing is saved. Closing Files, hiding the room or leaving the page retires a download that has not delivered its bytes.
- **Unavailable versions:** a row with `available: false` (the log still publishes it, but its bytes are gone from this gateway) stays listed with Download disabled, and a download refused with `attachment_unavailable` turns its row the same. Temporary refusals (`runtime_coordination_required`, `storage_unavailable`, `-32601`, no answer within 10 seconds) offer **Retry**; access refusals (`permission_denied`, `profile_mismatch`, `authority_conflict`, `room_history_expired`) do not.
